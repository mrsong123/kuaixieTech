# 商品成单、库存与店铺订单归因

PC/H5/小程序/App 商品详情已嵌入同一结账模型，选择商品卖家的可用普通行程、数量、地址及自主保险选择；由后端返回价格、托管额、保证金及有效时限，用户确认后才创建托管订单。金额保持精确人民币小数字符串，前端不决定收费。

公开候选行程、报价和创建三处执行同一核心条件：商品在架且有可售库存、有效认证卖家、关联店铺营业、同一卖家有效公开已审核行程、品类适配和可用名额。商品直购首期仅 solo，拒绝 pool，避免进入缺少 pool_slot 生命周期的路径。原有普通/竞价拼团流程保留，不宣称新增商品拼团闭环。

报价包含 productFingerprint（名称、规格、产地、分类、说明、图片、单价和店铺绑定），创建携带确认指纹、单价及托管额。锁后重新核对标的、分类、资格及容量，防同价换品和锁等待期间资格被撤销。新商品/旧意向创建统一排序锁买卖双方资料行并使用 READ_COMMITTED；不保证旧系统其他所有链路没有死锁，事务回滚与保留原幂等请求重试仍是必要边界。

创建事务内同时减可售库存、写订单/托管、扣钱包、写 t_product_order_reservations，失败全部回滚。该表保留买卖双方、商品/店铺/行程、数量、价格、货款/服务费、库存状态及不可变请求快照；买家同一请求键只能对应同一内容，成功重放不再扣钱扣库存。

库存状态 held → consumed / released：采购确认或完成消耗预占，采购前取消/超时释放一次；已采购后取消不会自动把货物加回库存，退货实物入库需另外审核。released 不得再用于完成。现有取消、超时、采购、无登机退款、结算等路径已挂接同事务库存辅助逻辑，旧订单没有预占记录时不改库存。

卖家编辑已参与商品交易的库存时必须提交载入时 expectedStock，旧表单不得覆盖新的预占。存在 held 订单时禁止把原商品名称/规格/产地/分类/说明/图片改成另一个标的；允许明确补货、未来报价修改及下架。锁产品后使用当前读取，防旧重复读快照漏判。图片按 JSON 语义比较，格式空格不会误判换品。

店主和管理员均有店铺订单分页出口，显示原订单货款/服务费快照及 held/consumed/released，不额外按店铺参考费率扣收，也不向店主暴露非必要买家联系方式。本人订单详情和原履约流程继续处理订单。购物车批量结账、购物车库存预占、境外店铺证照及新的店铺分佣规则仍未实现。

保险报价绑定商品名、声明价值与选定行程。保费不进平台钱包；报价不是保单，实际履约仍需有效保单或用户明确放弃保险。商品名称长度已与订单/原商品 255 字段对齐，003 尚未执行的保险报价建表同步调整。
