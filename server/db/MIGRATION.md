# 当前数据库对齐状态

`reference/current-schema.sql` 是用户提供的 82 表 SQL 原件。它是结构参考，包含建库、种子数据和触发器，**不得作为业务库更新脚本整体重跑**。应用已明确关闭 Spring SQL 自动初始化，并移除了登录服务启动时的建表/改表行为。旧 `src/main/resources/schema.sql` 属于另一套历史模型，目前未执行，也不是本次结构基准。

`t_integration_vendors/products/product_fields/settings/secrets` 保留为既有厂商、产品和字段目录。方案中的渠道表用于保留旧 RPC 契约，尚未完成统一运行时适配，不能把“已启用”或历史探测结果当作供应商当前可用，也不会自动复制密钥。统一渠道目录与运行时适配需要后续联调。

## 只读结构核验

在 `server/` 执行：

```sh
python3 tools/audit_schema.py
python3 tools/audit_schema.py --include-proposal --contract /tmp/kuaixie-contract.tsv
java --class-path /path/to/mysql-connector-j.jar tools/DatabasePreflight.java /tmp/kuaixie-contract.tsv
```

第一条会列出原始 82 表与当前代码之间的缺口；第二条比较包含增量方案的表/实体字段名，并生成契约。它不证明 SQL 语义或数据库实际运行正确。第三条需要实际配置 `DB_URL`、`DB_USER`、`DB_PASSWORD`，仅查询 JDBC 元数据并回滚只读连接，不导入 SQL、不查询业务数据。请使用启用证书验证的 JDBC 连接配置；私有网络还需要环境的 TCP/VPN 访问许可。密码仅通过环境设置配置，不写入命令或提交文件。

目前这些变量没有注入，真实库核验、迁移执行和业务流程联调均未完成。用户已指定将迁移汇总留至最终部署执行；当前开发阶段不执行，部署前仍需对照真实结构核验。

## 已完成的代码适配与边界

- 门户查询补齐；发布求购、社区审核、客服会话使用当前 `t_*` 表名。
- 个人资料、订单、求购、行程、钱包、账本、通知接口补齐；身份来自已验证会话，个人查询包含归属条件。
- 移除实体中的不存在字段；国家筛选读取 `t_category_countries` 的全部关联，由共享 SDK 统一处理。
- 登录不再自动创建管理员或修改结构。管理员初始化仅可在明确配置的 dev/local 环境使用；生产缺省关闭。
- 手机字段适配：现有大陆手机号保持原值，新增国际手机号存区号加号码，不增加 `phone_country_code` 列。上线前须核实存量国际手机号格式，避免错误解释历史数据。
- 移除了配置中的数据库密码、JWT 密钥和初始化管理员密码默认值。`APP_JWT_SECRET` 应安全配置为现有有效签名密钥以保留会话兼容性；不要直接将此变更部署到未配置密钥的环境。

已确认的机构直付流程使用 `escrow_v2_external_insurance`：后端统一计算 5% 服务费、货值 20% 的带货人履约保证金；交易托管不再收取平台固定保价费。客户选择保险机构和险种后，必须取得有效机构报价，另行同意条款并直接向机构支付保费。只有核验有效保单后才视为保障生效。原 `escrow_v1` 订单保留此前 1% 且最低 5 元的历史收费快照，须单独核对，不自动追认为真实保险。详见 [商品保险接入说明](GOODS_INSURANCE.md)。

意向确认要求请求 UUID 和确认金额，相同账号的同一请求重试返回原单；请求键复用于不同输入会被拒绝。PC 和移动端保留页面内未决交易请求，页面重载后的意向请求恢复仍待完善。保险申请使用独立的持久幂等引用，网络不确定时不会重发投保。

新版本邮费由买家查看金额并确认后追加托管，确认金额过期会被拒绝；结算拒绝支付未托管邮费，无凭证而未使用的托管邮费退回买家。新版本结算不再从买家余额重复扣保价费，并退回已冻结的带货人保证金；退税已单独划转的情况下，不再二次从货款扣除。旧订单保留原有计账逻辑，必须先对账后决定迁移，不能宣称历史账务问题已修复。新订单确认后交易托管金额锁定；尚未提交保险申请时可以针对原订单重新选择产品并报价，正式投保后变更须遵守机构撤销及重投协议。

意向有效期缺省为 24 小时，可通过 `app.orders.intent-hours` 配置 1–168 小时；超时任务仍默认关闭，启用前需确认运营规则。商品发布、本人编辑及上下架已补齐 PC 和移动入口；当前编辑器尚需图片上传及分类选择交互。完整业务闭环尚未完成：真实支付/退款回执、纠纷退款执行及部分 V14/V15 流程仍需实现或联调。没有改动分销费率，没有触发真实资金操作。
