# 商品交易纠纷与售后

本轮接通前台、管理端与 Spring Boot 的纠纷流程，不宣称真实退款、保证金划转或保险赔款已经接通。适用于普通与竞价订单，不修改历史订单金额和分佣规则。

## 权限与状态

仅买家可对 purchased/shipped/delivered/completed 订单发起申请。双方可查看自己的纠纷、补充说明和材料、申请平台介入。管理员才可记录裁决，身份从服务端获取。

| 当前状态 | 操作 | 后续状态 |
| --- | --- | --- |
| 无活动纠纷 | 买家发起 | negotiating |
| negotiating | 双方回应 / 申请介入 | negotiating / platform_review |
| platform_review、appeal | 裁决退款或货款补偿 | awaiting_refund |
| platform_review、appeal | 裁决补发 | awaiting_fulfilment |
| platform_review、appeal | 驳回 | resolved |
| awaiting_fulfilment | 买家确认实际收到补发 | resolved |
| resolved、awaiting_refund、awaiting_fulfilment | 一次申诉，退款未在途/完成且无另一活动纠纷 | appeal |

协商窗口缺省 48 小时，`app.disputes.negotiation-hours` 可取 1–168。超时仅要求平台介入，不自动判胜。同单只允许一个活动纠纷。每次变更递增 round，旧版本写入拒绝覆盖，要求刷新详情。

## 幂等与材料

写操作必须携带 UUID。创建以账号/请求键确定工单 ID；事件按工单/操作者/请求键去重并核验请求摘要。同一键不能改变请求内容。共享 `useTradeCases.ts` 保留页面内未确认请求，网络异常或格式错误响应可重试原请求；页面重载恢复尚未实现。

`004-dispute-events.proposed.sql` 提议增加事件表，**未执行**。应用仅追加事件，不提供修改/删除接口；未宣称数据库管理员无法篡改。客户时间线隐去审核员身份和内部摘要。

允许文字申请、随后补材料。每次最多四条，每方累计最多二十条。后端只接受 `kuaixie.portal.allowed-media-hosts` 配置域名的 HTTPS 链接，不接受用户信息、片段或非标准端口；缺省无域名则拒收链接。不代表文件已上传、归属已验证或材料真实。上传 ID 关联、存储、检测与审核仍待文件服务联调。旧记录材料可在详情查看。

## 资金与售后

金额为精确人民币小数，本流程仅处理货款退款/货款范围内补偿。累计同单其他未取消退款工单金额不得超过货款；服务费、邮费、保证金、保险费不自动并入。

退款裁决写 `t_after_sales_cases`，ID 与纠纷相同，保存商家回应和平台意见。退款状态为 provider_unavailable，界面显示尚未退款，不能人工伪造到账。真实执行、回执和结案尚需实现。已在途/完成退款不可重判或申诉，须先对账。申诉暂停未执行退款。

保证金归属仅处理意见，不执行划转。保险理赔由承保机构独立处理，平台不代其赔付或垫付。本服务无钱包或保险资金调用。

订单加锁后检查未结束纠纷和售后，阻止自动完成结算、发货确认、取消资金处理、未登机退款绕过流程。管理员取消同样先锁订单，避免并发创建纠纷与资金处理竞态。既已完成订单保留结算幂等返回，不重新入账。

## 入口和验收

PC 服务目录/买家订单详情、H5/小程序/App 服务目录/买家订单/原纠纷页共用业务模型；管理后台“纠纷”提供队列、材料、裁决和时间线。邀请等级另有 PC/移动读取入口，读取现有等级、有效邀请数、积分和当月已记录佣金，GET 不重新计算或发放。

测试覆盖权限、状态、轮次、幂等、证据域名、退款上限和资金阻断，使用模拟 JDBC/Mapper，不能替代真实 MySQL 事务、历史数据、并发与真机验收。真实库缺连接配置，001–004 均未执行，所有字段仍待完整验收。
