# 店铺申请、经营与商品关联

前台服务目录“我的店铺”提供经营资料、本人执照上传、申请历史、店铺资料、营业状态和本人商品关联；后台交易业务新增“店铺审核与经营管理”；公开商品详情可进入其有效店铺，店铺商品分页进入原商品详情。

本轮使用既有 t_store_applications、t_stores、t_community_uploads。申请按账号和 UUID 确定 ID，同键不同材料拒绝覆盖；账号行锁串行化同一人的申请与审批。18 位统一社会信用代码校验字符和校验位，首版是境内执照，不把境外注册号存为中国信用代码。邀请码核对有效邀请人，仅记录来源，不改分佣关系或发奖励。

执照必须是本人、store_license 用途、有成功上传元数据的私有附件。申请原子消费附件，不接受任意 UUID、他人文件或已使用附件。格式与摘要不等于企业真实性核验，运营须下载材料审核；该审批不会自动完成企业 KYC、承运认证或保险核验。

管理员在 pending 上审核并留意见、身份、时间与日志；通过才创建唯一店铺。相同审核者和相同结论/意见可安全重放，不重复建店；其他覆盖拒绝。拒绝后可重新上传材料并提交新申请，旧记录保留。

店主可维护名称、介绍，切换 active/paused；suspended 仅管理员解除，并先恢复为 paused。停用后的商品关系不可由店主解除来绕过限制。公开店铺及关联商品隐藏；商品目录、详情、购物车、收藏同步检查店铺状态。既有订单快照与履约不因店铺展示状态改变，账号封禁仍是另一项运营权限。

新增 `005-store-products.proposed.sql`，只增加 t_store_products 关联表，保留绑定者与时间；每个商品至多归属一个店铺，且归属必须与商品所有者一致。新增关联要求认证带货人，活跃所有者可移除关联（运营停用除外）。公开商品还须在架、有库存、卖家有效且承运认证通过。前台、后台和 SQL 都不允许指定别人的商品或借绑定改变商品所有权。

matching_fee_rate 保持既有 5% 存储值并只读展示参考，不产生额外扣收；当前订单沿用后端报价。本轮已补店铺订单归因、库存占用与单商品成单；新的费率/分佣规则、批量购物车和商品拼团仍待实现，不能仅因有公开店铺就宣称完整店铺交易已闭环。

t_store_insurance_policies、t_insurance_coverages 与新保险订单的数据边界仍待整理和真实机构核验。店铺审核不提供保单真实性保证，不改写保险状态或动用平台风险池。

所有数据库写入只发生在实际业务接口被授权调用时；本轮未连接真实业务库，未执行迁移。单元、契约和构建通过不能代替真实 MySQL 事务、存储联调及五端真机验收。

本轮新增店主/管理员店铺订单分页及库存状态出口，见 [PRODUCT_CHECKOUT.md](PRODUCT_CHECKOUT.md)；不额外按店铺参考费率扣收。
