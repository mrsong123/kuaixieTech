## 合成夹具及验收边界

- 首次运行通过实际本地 bootstrap 登录建立管理员。后续复跑不重置、不清库：工具仅在标记为一次性审计的容器插入一个新的合成管理员资料，再通过真实 `/auth/login` 设置本地 bootstrap 密码并签发令牌。收据明确记录该管理员资料属于 SQL 夹具。
- 买家、带货人的注册验证码直接插入临时库，随后执行实际注册和密码登录。没有验证短信或邮箱的申请、发送、运营商受理、终端送达。
- 两个用户的实名认证通过状态由 SQL 夹具赋值。没有调用供应商实名 API，也未经过后台认证审批。
- 1000.00 CNY 钱包余额及 `test_seed` 开账分录为合成夹具。没有真实充值、银行回单、支付回调、生产退款或结算。
- 两个地址均为合成资料，经真实 HTTP 创建、切换和读取，保留在一次性审计库；没有清理或删除其他账户的地址。
- 没有手工伪造 JWT：管理员和用户令牌均来自本次运行的真实登录/注册端点。密码、JWT 签名密钥、配置加密根密钥均在进程内随机生成，不写入收据或仓库。
- 本次没有覆盖 PC 界面浏览器交互、HBuilderX、微信开发者工具、Android、iOS、真实微信登录和文件上传；这些不能由 HTTP 成功代替。

## 复跑方法

预先在本机准备带上述明确标签的官方 MySQL 容器及完整 113 表临时结构。在仓库根目录执行：

```bash
python3 server/tools/runtime_smoke.py --confirm-disposable-database
```

工具固定使用本机 Docker socket，忽略外部 Docker selectors，检查镜像、用途标签、本机端口、113 表数量，并覆盖 `DB_URL` 为 `127.0.0.1:13307/suixinggou`。它拒绝其他数据库端口，不会读取调用环境的业务库地址执行夹具。不能把业务容器改名或加标签后用于此测试。

本轮结束后已受控停止上述一次性数据库容器，保留其审计数据；复跑前仅启动同一个带专用标签的本地审计容器，不能改指业务库。

工具默认使用本环境 `/workspace/tooling` 中的 Maven、JDK 和缓存；其他环境可用 `--maven`、`--java-home`、`--settings`、`--repository` 指定已安装工具。Docker 权限或本机网络限制可能需要执行环境许可。默认结果 `/tmp/kuaixie-runtime-smoke.json`，服务器日志 `/tmp/kuaixie-runtime-smoke-server.log`。审阅并复制脱敏收据后提交；原始服务器日志留在临时目录。每次复跑添加新的随机合成用户和商品，不删除既有数据。

本轮没有业务数据库连接配置和供应商商户凭据。下一步应继续按主清单完成剩余模块，并以同样的真实运行方式逐条添加业务断言；只有具备授权配置及正式供应商回执后，才能标记对应真实服务验收通过。
