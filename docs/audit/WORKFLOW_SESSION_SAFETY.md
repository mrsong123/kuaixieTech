# 通用业务流程与原生接口工具：P1账号/目标隔离

本次修复的是已存在界面的异步操作风险，没有把动态RPC表单或接口工具升级为正式业务闭环。

## 已修复

- `useBusinessWorkflow`绑定最初会话；换账号即清空表单、路由上下文、保险标的和回执。销毁后旧请求/确认框也不能继续操作；A→B→A不会恢复旧请求。
- 接单先读保证金、竞价成单先取报价、接受邮费先读费用。每次读取和确认之后都重新验证账号、操作和表单快照，再提交原服务端金额；未改变费用、交易参数或后台状态协议。
- 通用危险操作在打开确认框前即锁定，避免重复点击弹出多个确认并多次发请求。已有请求字段按原值捕获，不重新生成或替换请求标识。
- 表单或目标被外部上下文更换时，旧确认/报价不再提交；旧成功回执和错误也不会填入新目标。界面忙碌时禁止编辑对应字段，不修改原样式。
- 原生`useToolsPage`在弹出`uni.showModal`前捕获操作、路径参数、查询和请求体。换账号、换目标、切换操作或销毁后，旧确认不调用新账号API，旧响应不显示或弹窗。管理员专用操作仍拒绝从普通客户端接口工具执行。

## 未完成的业务边界

通用流程仍主要是自动生成字段表单与RPC结果展示，完整的采购证据、物流、核销、发票等业务界面和实际服务回执仍需逐项实现/验收。界面有按钮和RPC有声明不能证明该动作真实可用。

这些旧通用操作并没有统一的前端pending恢复协议。此次不虚构通用幂等键、不增加自动重发，也不把未知响应改为成功；有请求标识的原字段原样提交，无后台幂等协议的动作仍需后续专项补齐，不能宣称跨关闭/重启不重复执行。

验证使用真实Vue模型、SDK会话与延迟Promise/原生modal夹具，覆盖接单/竞价/邮费及通用危险确认、换目标、重复点击、销毁和迟到回执；未向真实业务库或供应商发送请求。


复核留项：移动API工具页在换账号后会安全清空selected并停止操作，但错误提示仍放在selected卡片内，导致“重新打开页面”提示不可见（`client/apps/mobile/src/pages/tools/index.vue`）。属于待改进的可用性反馈，不影响本轮拒绝旧确认/旧回执的保护，也未标成已完成。
