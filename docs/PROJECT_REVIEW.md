# 项目功能与持续复盘

更新：2026-11-01。本轮按用户授权由商品后端、退款后端、邮件、商品界面、退款界面、独立审查六个代理并行，主代理统一集成、验证与汇总。前一轮基线为当前应用 167 项后端测试、27 项共享模型断言，含提议表 102 表/1078 字段。所有验收状态继续保留 pending。

## 系统定位

这是买家与随行带货人的交易撮合平台：求购、商品和行程促成交易，经托管、采购取证、邮费确认、发货/交接、收货与结算完成履约，配套店铺、社区、客服、邀请奖励与运营审核。

订单及钱包以人民币记账，付款币种由真实收单能力决定并采用后端有效期报价换算；币种目录不是渠道已支持证明。客户自主选择保险机构/险种，机构定价、直接收费并承保，平台不作为保险担保方，不代收或托管保费。

## 本轮复盘中发现并修复的问题

- 相同价格下更换名称、规格、产地、分类、说明或图片，旧报价仍可能买到新标的；现增加完整商品指纹并在锁后复核。
- 旧库存编辑表单与重复读旧视图可能覆盖新预占；现编辑使用 READ_COMMITTED 与载入时库存确认，held期间冻结标的。
- 商品拼团订单缺 pool_slot 生命周期；当前明确限定普通solo行程，不宣称已支持商品拼团。
- 买家权限可在等待账户锁时失效；现锁后重新验证，旧意向和新成单统一局部账户锁顺序。未宣称旧系统所有链路无死锁。
- 退款坏PEM或过长微信理由可能在提交claim后才失败；现本地解析/试签/请求预检在claim前完成。
- 取消或驳回后永久不能重新申请不是已确认业务标准；现只允许未派发且预留已释放的历史申请放开新attempt，旧历史不可覆盖。
- 原收款receipt漏精度必填列，账务类型超过原库16字符；已修复并补回归保护，不修改历史余额或分佣费率。
