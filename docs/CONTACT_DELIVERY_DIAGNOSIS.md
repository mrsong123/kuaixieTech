# 验证码调度故障诊断与本次修复

用户日志中 `CONTACT_DELIVERY_PARTIALLY_UNAVAILABLE` 只表示短信/邮件配置探测或发送阶段至少有一项抛错。旧调度捕获后丢弃原始分类，再统一抛出此异常，因此仅凭这段堆栈不能确定是缺数据库迁移、数据库连接失败、缺密文根密钥、配置损坏还是厂商外呼失败。不能据此声称只是“缺少短信配置”。

## 代码修复

- 短信和邮件仍独立探测、独立执行，一通道故障不阻断另一通道。
- 未配置的通道为 `idle`，SANDBOX/停用或未选中通道为 `paused`，不会领取发送任务。此状态不表示注册验证码已可用。
- 缺表/缺列、数据库不可用、密文不可读、配置错误以及派发不确定分别记录安全原因码、阶段、异常类型、SQLState和数据库错误码；缺表时仅提取安全的表名，不输出数据库名称、SQL或连接凭据。
- 调度不再每分钟抛出无根因的统一异常。状态改变立即记录，持续故障每10轮重复提示；仍保留非ready诊断及管理员查询入口，避免把修复变成静音。
- 旧worker在发信超时、回执异常或回执落库失败时会直接返回，调度无法看见失败。现在向调度报告安全的 `SMS_DISPATCH_UNCONFIRMED` / `EMAIL_DISPATCH_UNCONFIRMED`；原claim继续保持blocked，不自动重放。明确拒绝或非法输入则保留失败结果，不能被当作发送成功。
- 不可读配置、SANDBOX/功能停用、已存在原生配置或发送故障均不允许转用旧整队列桥接，避免重复发信和计费。

## 管理员只读健康接口

`GET /portal/admin/contact-delivery/health`（网关转入 `/api/...`）要求管理员身份。

接口只探测配置和读取队列状态汇总，不领取验证码、不发送邮件/短信，不返回手机号、邮箱、验证码、密文或原始异常消息。返回当前配置状态、上次调度阶段、队列各状态计数；有blocked尝试时标记需核对。`sent` 只表示供应商接受，不表示手机/邮箱实际收到；`providerDeliveryVerified` 保持false。

| 状态 / 原因码 | 意义与后续动作 |
| --- | --- |
| `idle` | 没有启用的有效发送通道，先配置合作渠道；无法证明注册/找回密码已可用 |
| `paused` | SANDBOX、功能关闭、配置停用或未选中；按预期暂停，不绕过模式限制 |
| `migration_required` / `CONTACT_SCHEMA_MISSING` | 实际库缺代码依赖表；以返回表名核对information_schema和已审阅增量SQL，不盲目重复导入完整结构 |
| `CONTACT_SCHEMA_INCOMPATIBLE` | 实际列与代码不一致，先核对结构及待执行迁移 |
| `database_unavailable` | 检查数据库服务、连接参数、目标库存在性、网络和账号权限，勿在聊天贴密码 |
| `credentials_missing` | 检查 `INTEGRATION_CONFIG_KEY` 或明确引用的环境变量是否通过部署环境提供 |
| `credentials_unreadable` | 确认根密钥存在且与保存密文时一致；不要用新密钥覆盖旧密钥后伪称可以解密 |
| `configuration_invalid` | 核对地区、模板/发件身份、必要字段、供应商互斥和已实现的业务消费者 |
| `dispatch_unconfirmed` / `requires_reconciliation` | 原尝试保持blocked；先查供应商结果及账单，不自动重新发送或计费 |
| `dispatch_failed` | 已记录明确拒绝或输入错误，检查对应安全原因码，不把失败视为送达 |

## 验证及限制

新增测试验证缺迁移的脱敏根因、缺根密钥与坏密文、SANDBOX不读密钥/不领任务、健康接口只读且仅管理员、未知回执绝不重发，以及一通道失败另一通道继续。原有两通道独立与安全claim测试继续验证；旧测试中要求统一抛错的断言改为要求可追踪的degraded状态，未放松防重复发送约束。

没有连接用户业务库，没有执行迁移或真实短信/邮件。用户本机准确根因须根据修复后的安全日志/健康接口或实际结构核对；只有真实发送及接收回执验证后，才能把验证码业务标为已跑通。


## 后台配置窗口

管理员进入“云产品密钥”后，可在“验证码投递诊断”区域只读刷新。窗口分别展示短信、邮件当前配置与上次调度，提供缺表名称、安全原因码、SQLState和队列状态计数；没有测试发信、重发或收费按钮。阻断记录提示先等待在途请求或核对供应商，不按“sent”假定实际收件。

页面在账号切换、组件销毁或刷新失败后清掉旧结果，晚响应不能用旧的ready覆盖新故障。新增前端专项16项断言与完整admin类型检查通过；验证使用离线API夹具，没有向真实服务发信。字典已合并，管理端资源构建通过；用户环境与真实送达仍待验证。
