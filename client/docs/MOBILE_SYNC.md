# 小程序与 App 业务同步

本次按用户要求，将已新增的业务入口和修复同步至微信小程序、Android/iOS 共用的 UniApp 资源，并保留当前移动端设计。没有套用 PC/后台的纸色主题，也没有将管理员密钥配置权限开放给普通客户端。

| 功能 | 移动端入口与同步内容 |
| --- | --- |
| 求购、行程、文字动态 | 发布页统一字段/日期/容量校验；金额保留十进制字符串；真实回执区分已发布与待审核 |
| 发布入口与登录返回 | “我的”发布行程/求购进入对应模式；登录仅恢复白名单模式和区域，不在 URL 中传草稿或任意跳转地址 |
| 商品发布与图片 | 保留商品分类、上传、认证预览、本人未用图片复用/删除及库存保护；商品模式不会误发社区动态 |
| 商品下单 | 保留原服务端报价、确认指纹、托管下单与机构直付保险选择；社区商品锚点进入公开商品详情 |
| 店铺 | “我的”直达申请、经营管理、商品关联及订单归因；店铺页面按账号重建，执照和旧确认回调不能跨账号 |
| 保险 | “我的”直达保险记录、订单选择和同意记录；机构独立定价收费承保，平台不担保，报价/投保旧响应不回填新账号 |
| 订单与凭据 | 个人订单、意向和列表清理旧账号状态；历史订单商品图继续通过参与人鉴权读取 |
| 售后 | “我的”直达售后；案件 ID 与订单 ID 分别透传；钱包退款回执、时间线与 PC 语义一致 |
| 原充值退款 | “我的”和钱包直达原路退款；保持与售后托管货款退回平台钱包两条资金路径分离 |
| 充值与汇率 | 旧报价/原生确认框/SDK 回调不能用于新账号；恢复记录仅按服务端验证的用户 UUID 和平台分区，不保存 JWT |
| 附件与外部页面 | 原生上传、下载、图片/PDF打开均核对会话代次；换号即清旧支付/保险网页地址，晚回执不重新打开 |
| 服务导航 | 补齐我的求购、店铺、保险、售后、退款、服务目录及邀请等级等已有功能入口 |

首页订单资金说明同步到当前 PC 口径：按订单规则及裁定处理取消和售后，不笼统承诺所有情况都按同一比例扣款；保险独立于平台托管。

## 验证

- PC、后台、H5、小程序与 App 资源构建全部通过；SDK及移动端完整类型、接口契约、翻译、显示偏好和包引用检查通过。
- 原有7组150项模型断言通过；新增发布26、店铺22、保险16、原生文件15、钱包23、移动业务19，共121项；合计271项断言通过。
- 微信产物校验83页、87处本地组件引用、339个静态依赖；本地文件约1.34MiB，正式包体积以微信开发者工具报告为准。
- 发布页、“我的”、钱包及共享店铺/钱包组件的原有 CSS 保持不变。新增入口使用现有行组件和主题。
- 后端、数据库和迁移均未修改，没有真实资金操作或供应商调用。App资源构建不是Android/iOS签名安装包或真机验收。

## 保留边界

发布接口本身尚无跨重启的服务端幂等协议。本次未知结果保护仅限当前表单：先核对本人记录，再显式允许重提，解锁按钮不会自动发送；不能宣称关闭/重启后绝不重复发布。

充值恢复只读取当前已验证用户分区中的订单 ID/原报价 ID 与幂等键，再通过本人受保护接口核对；旧平台级缓存只清理、不采用。客户端或支付 SDK 的回调不作为付款入账证明。

原生登录、支付、投保和 App 发布仍需各自已授权的 AppID、渠道配置、真实回执及真机验收。未实现的视频上传、供应商适配或银行通道不会因界面同步而被标记为已接通。
